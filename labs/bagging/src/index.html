    Bagging means bootstrap aggregating. Draw a training sample with replacement, fit one model on it, then repeat for the other models and combine their predictions.

    Draw from the parcel desk

    Each original parcel remains eligible after every draw.

      Another draw is another training occurrence. If P2 appears three times, it counts three times when the tree tallies labels. A row never drawn is out of bag for that tree.
      What changes without replacement?

      With 12 draws from 12 rows and no replacement, every row appears once. Drawing fewer than 12 without replacement would give a subset with no repeats. With replacement, repeated and omitted rows can occur even when the number of draws equals the original row count.

      How do we combine the predictions?

      For classification, one simple approach is to count the predicted classes and choose the majority. Another approach averages probabilities by class. For numerical regression, average the predicted numbers.

      We have three different samples. Give each one to its own tree and follow the same new parcel through all three.

      Random Forest intuition

      Train three trees and combine their answers

      Each sample trains one decision tree with the same settings. A Random Forest adds randomized feature choices at each split. We’ll isolate the row sampling first so we can see where the differences come from.

      Is vote share the same as average predicted probability?

      Each hard vote contributes one class. In a probability average, a leaf with two Review rows and one Auto row contributes a Review probability of 2/3. For example, three Review probabilities of 0.49, 0.49 and 0.99 give two Auto hard votes but a mean Review probability of about 0.657. In scikit-learn, the forest classifier picks the class with the largest mean probability.

      Different rows can change an entire tree. Next, see how changing the candidate features can change just one question.

      How do we get different trees?

      Change the rows and the candidate features

      Each tree draws its own training rows. At each split in a Random Forest, it also samples candidate features. The best eligible question is chosen using the rows that reach that node.

      A different candidate list at each node

      Use rows from Tree 2’s bootstrap sample. Inspect the root and its Yes child.

      These are seeded candidate-list comparisons at two fixed nodes from the original tree. A forest fits its own downstream nodes after each selected split.

      Rows are resampled per tree. Candidate features are sampled per split. Both changes can reduce how often the trees make the same mistakes.
      Does choosing fewer features always help?

      Fewer candidates can diversify trees. It can also hide a strong feature at an important node. Compare settings on validation data. A feature can be eligible again at another split.

      What happens to a feature that was unavailable at this node?

      It was skipped only for this candidate draw. A later node can sample it and use it if it has a valid split.

      Different decisions are useful when the individual models still capture some signal.

      Properties of base learners

      Useful alone, better able to disagree

      Decision trees can learn interactions, such as a scan cutoff that applies only to heavier parcels. Deep trees can also be sensitive to small changes in the training rows. Aggregation helps most when useful trees’ errors are less correlated.

      Change the maximum depth

      Should every tree be weak?

      Bagging is especially helpful for learners that are sensitive to their training data, such as deep trees. Useful trees can vary in complexity. Shallow trees may miss an interaction. Deeper trees may pick up details that change from sample to sample.

      What if every tree makes the same mistake?

      Every vote points the same way, so the aggregate makes that same mistake. For a numerical prediction, averaging identical numbers also leaves the prediction unchanged.

      1. Split once. Set aside a stratified test set, which keeps roughly the same class proportions. Keep test labels out of model selection.
      2. Fit both baselines. Train a decision tree and a Random Forest on the same training partition.
      3. Define a search space. Pick plausible list values or distributions for the settings. Decide how many combinations to sample.
      4. Search on the training set. Each candidate fits the training part of each fold and scores its validation part. Choose the best mean validation score.
      5. Evaluate once on the holdout. Refit the selected settings on all training rows. Inspect precision, recall and the confusion matrix on unseen parcels.

      How does randomized search differ from a grid?

      A grid enumerates the specified combinations. Randomized search evaluates a budget of sampled combinations. The search reports the same kind of cross-validation scores for each candidate. RandomizedSearchCV reference

      Why balanced accuracy?

      It averages recall across classes, so both Auto and Review count equally even if their frequencies differ. For the parcel desk, also report Review recall and precision so you can reason about missed checks and manual workload.

      Cross-validation reserves folds. Bootstrap sampling gives us another source of unused rows, one set for each tree.

      How does a forest compute feature importance?

      For each tree, credit a feature with the weighted impurity decreases from the nodes where it splits. Sum repeated uses within the tree, then combine the tree-level importances and normalize in the forest.

      Impurity-based importance describes how this forest used its inputs during training. Features with many possible split points can get extra credit. Held-out permutation importance asks how much a chosen score falls when a feature’s values are shuffled.

      Why can more trees give diminishing returns?

      More trees stabilize the average for fixed training settings. Similar trees share part of their error, and adding estimators cannot fully average that part away. Check validation gains and compute together.

      How do depth and pruning differ?

      Maximum depth stops growth once a path reaches a specified limit. Minimal cost-complexity pruning removes branches according to the balance of impurity and tree size. A larger ccp_alpha favors simpler trees. Both settings can trade variance for bias.
