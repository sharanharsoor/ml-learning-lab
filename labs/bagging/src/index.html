    Bagging

    Give each tree its own sample drawn from the courier’s records. Train the trees separately, then combine their predictions for the new parcel.

    Boosting

    Build the trees in order. In gradient-boosted decision trees (GBDT), each new tree learns a correction to the current model. If the model keeps missing parcels that need Review, the next tree can learn a pattern that helps correct those predictions.

    Stacking

    Give a second model the first models’ predictions as inputs. For example, it can learn how to combine a decision tree’s answer with a logistic regression model’s answer for each parcel.

    Cascading

    Send parcels through models in stages. A quick first model can route a clear case immediately. If a parcel is borderline, pass it to a second model with more measurements for a closer decision.

    What changed between the two trees?

    When a tree compares possible cutoffs, it counts the Auto and Review rows on each side. A new sample can repeat some rows and leave others out. That changes the counts, so a different cutoff can work better for that tree.

    How does stacking get examples for the second model?

    Set aside a group of past parcels. Train the first models on the rest, then ask them to predict that group. The second model learns from those predictions and the group’s recorded routes. Rotating which group we set aside gives us predictions for more parcels. These are called out-of-fold predictions.

    Draw a bootstrap sample

    The courier has 12 past parcel records. We want to give each tree its own training sample. How can we do that with the same 12 records?

    Bootstrap · Fill one tray per tree

    Make 12 draws from the original pile. Since every ticket goes back, you might copy one parcel twice and miss another entirely. That new tray of 12 draws is one bootstrap sample. Start again from the same original pile for the next tree.

    Aggregate · Combine the trees’ answers

    Train each tree on its own tray. A different mix of records can change the questions a tree learns. Then give every tree the same new parcel. If two trees say Review and one says Auto, a majority vote gives Review. Combining the answers is aggregation.

    Bagging is short for bootstrap aggregating. Make a training sample for each model, then combine their predictions so the final route depends on several models.

      What changes without replacement?

      With 12 draws from 12 rows and no replacement, every row appears once. Drawing fewer than 12 without replacement would give a subset with no repeats. With replacement, repeated and omitted rows can occur even when the number of draws equals the original row count.

      How do we combine the predictions?

      For classification, one simple approach is to count the predicted classes and choose the majority. Another approach averages probabilities by class. For numerical regression, average the predicted numbers.

      Random Forest intuition

      Train three trees and combine their answers

      Each tray holds a different mix of the courier’s past parcels. Give one tray to each tree and let it learn which questions separate Auto from Review. When the new parcel arrives, give all three trees its same measurements and see whether they agree.

      These three trees demonstrate bagging with both features available at each split. The next chapter adds the feature sampling used by Random Forest.

      1. Sample. Make a tray of 12 draws for each tree. Each time you pick a row, keep a copy in the tray and allow the original to be picked again.
      2. Fit. Train each tree on its own tray. It uses the recorded routes to choose questions such as “Is the scan score at most 5.8?”
      3. Predict. Give each trained tree the same 5.65 kg parcel with a scan score of 5.7. Answer its questions until you reach a leaf, the group where that tree makes its prediction.
      4. Combine. Each tree can vote Auto or Review. We can also average the Review probabilities from the three leaves. Either rule gives the courier one final route.

      Hard vote. Two of three trees say Review, for a Review vote share of 66.7%.

      Probability average. The Review shares inside the reached leaves are 0/8, 7/7, and 2/3. Their average is 5/9, or 55.6%. That also gives Review the larger share for this parcel.

      Is vote share the same as average predicted probability?

      Each hard vote contributes one class. In a probability average, a leaf with two Review rows and one Auto row contributes a Review probability of 2/3. For example, three Review probabilities of 0.49, 0.49 and 0.99 give two Auto hard votes but a mean Review probability of about 0.657. In scikit-learn, the forest classifier picks the class with the largest mean probability.

      Does choosing fewer features always help?

      A shorter list gives the tree a chance to use a different measurement. It can also leave out a strong feature that would have separated Auto and Review better. Try several list sizes and check which one predicts better on validation data.

      Where does the 0.3111 Gini decrease come from?

      Gini measures how mixed the Auto and Review labels are at a node. The root has four Auto and eight Review draws, so its Gini is 1 − (4/12)² − (8/12)² ≈ 0.4444. The scan cut leaves four Auto and one Review in the Yes group and seven Review in the No group. Their Gini scores are 0.32 and 0, weighted by 5/12 and 7/12. Subtracting that weighted result from the root score gives 0.4444 − [(5/12 × 0.32) + (7/12 × 0)] ≈ 0.3111.

      Properties of base learners

      Useful alone, better able to disagree

      Tree 3 can ask about weight first, then ask about scan score on just one branch. That lets it learn a pattern that uses both measurements. Each tree is a base learner, an individual model that contributes an answer. When useful trees make different mistakes, combining their answers can give us a steadier decision.

      When a tree is too simple

      A tree with one question can miss a real pattern that depends on both weight and scan score. When the same pattern is missed across many new training samples, the model is underfitting and can have high bias.

      When a tree learns its tray too well

      A deep tree can capture that pattern and also learn a cutoff that matches a few unusual training tickets. Overfitting happens when fitting those details hurts predictions on new parcels. Flexible trees can reduce bias and become more sensitive to which rows they saw, increasing variance.

      Change the maximum depth

      Maximum depth sets how many questions a parcel can answer on its way to the tree’s decision. All three trees refit on their original samples so you can see what changing the limit does.

      The diagram shows Tree 3, which the example below compares at depths 1 and 2. Each card shows its tree’s answer for the new parcel and how many training draws it got right. A parcel drawn twice counts twice in that training total.

      Try it. Change depth from 1 to 2 and watch Tree 3. Its second question helps it get 11 of 12 training draws right, up from 10 of 12. It also changes its answer for our new parcel from Auto to Review. To judge whether the extra question helps with new parcels, test it on a separate group the tree hasn’t seen.

      How much should one tree learn?

      At depth 0 the tree makes the same call for every parcel. It picks whichever route appears more often in its sample. At depth 2 it can learn an interaction, where the value of one feature changes how another feature is used. For instance, it can ask about scan score for just the lighter parcels. Extra questions can also pick up patterns that were peculiar to this tray. Averaging several trees helps when those details send the individual predictions in different directions.

      What if every tree makes the same mistake?

      Every vote points the same way, so the aggregate makes that same mistake. For a numerical prediction, averaging identical numbers also leaves the prediction unchanged.

      Is the parent big enough to try?

      min_samples_split checks the parent before a split. A node with 10 rows qualifies at a minimum of 8. At a minimum of 11, it stays a leaf.

      Would both children be big enough?

      min_samples_leaf checks each proposed child. With a minimum of 3, a 9 | 1 split is ruled out while a 6 | 4 split clears that requirement.

      Which other settings can I change?

      criterion changes how a split is scored. max_leaf_nodes caps leaves, min_weight_fraction_leaf sets a minimum share of sample weight per leaf, and min_impurity_decrease requires a minimum weighted impurity drop. The search ranges should reflect the data size and the job the model has to do.

      Why balanced accuracy?

      Suppose 90 of 100 parcels are Auto. Sending every parcel to Auto would give 90% accuracy and miss every Review. Balanced accuracy finds the fraction correct within each actual route and averages those fractions. Here it averages 100% for Auto and 0% for Review, giving 50%.

      Interview questions

      Explain importance and tune the trade-offs

      A colleague at the courier desk asks two questions. Which measurement did the forest rely on, and what would change if we gave each tree a different depth limit? Start by tracing how a split earns credit. Then pick a setting and explain what it would change about the forest.

      How does a forest compute feature importance?

      Every draw reaches the first split in Tree 2. Its later weight question affects just the parcels that reach that branch. Impurity-based feature importance gives a question more credit when it separates the labels well and reaches more rows.

      Multiply each split’s impurity decrease by the fraction of training draws that reached it. Credit the feature used at that split. Add the credits for each feature, express them as shares of that tree’s total, then average those shares across the trees.

      When a tree splits but never uses a feature, it contributes zero for that feature. Tree 1 uses only scan score, so its weight entry is 0%. The ensemble average keeps that zero in the denominator. Scikit-learn skips root-only trees in this calculation.

      Work through the numbers for these trees

      In Tree 2, the scan-score split is at the root, so all 12 draws reach it. Its weighted credit is 12/12 × 0.3111 ≈ 0.3111. The weight split is lower down. Its weighted credit is 5/12 × 0.32 ≈ 0.1333.

      Those credits total about 0.4444. Dividing each credit by that total gives 70% scan score and 30% weight within Tree 2. Across the three trees, mean weight importance is (0% + 30% + 64.3%) ÷ 3 ≈ 31.4%. The other 68.6% goes to scan score.

      A feature with many possible cutoffs gets more chances to earn split credit. For a check on fresh data, shuffle the scan scores among the held-out parcels, keep each parcel’s other information in place, and score the same forest again. The drop in score tells you how much this forest relied on scan score in that test. This is permutation importance.

      Five settings, five different changes

      Pick one setting. Imagine keeping the other four fixed, then say which part changes. Does it affect the training tray, the questions a tree can ask, or the number of predictions we combine?

      Why can more trees give diminishing returns?

      If several trees already tend to give the same parcel the same answer, another similar tree adds little new information. More trees can steady the average and also take longer to train and use. Compare how much each increase improves the validation score.

      How do depth and pruning differ?

      Maximum depth caps how many questions a parcel can answer while the tree grows. Pruning checks whether a branch earns its extra size by improving the separation of the labels. A larger ccp_alpha makes that size more costly, so simpler trees are favored. A simpler tree may vary less with the training sample and also miss a useful pattern.

      When does a branch earn its place?

      Consider two possible subtrees from a parcel model. The four-leaf subtree separates the training labels better, so it has lower weighted leaf impurity. Each extra leaf comes with a cost. Move the penalty slider and watch which subtree becomes cheaper.

      Cost = weighted leaf impurity + α × number of leaves. Weighted leaf impurity adds each leaf’s impurity multiplied by its share of training weight.

      These are two illustrative pruning candidates. Starting with a fitted tree, cost-complexity pruning considers simpler subtrees. max_depth constrains the questions while the tree grows.
