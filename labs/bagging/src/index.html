    Bagging

    Give each tree its own resample of the training emails. Fit the trees independently and ask them all to classify the same incoming email.

    Boosting

    Build trees in sequence. In gradient boosting, each new tree learns a correction to the current model, for example to improve predictions on spam it often misses.

    Stacking

    Use a second model to learn from the first models’ predictions. It could learn how to combine a tree’s prediction with a logistic regression score for the same email.

    Cascading

    Apply models in stages. A quick filter can handle clear cases. It can send uncertain emails to a model that examines more signals.

    Where did the cutoffs come from?

    The tree compares possible cuts by how well they separate the recorded labels. A new draw changes which values and labels are available at each node.

    How does stacking get training examples?

    Set aside some labeled emails, train the first models on the rest, then have them predict the set-aside emails. Train the second model on those predictions and recorded labels. Rotating the set-aside group gives more examples. These are called out-of-fold predictions.

      Is vote share the same as average predicted probability?

      Each hard vote contributes one class. In a probability average, a leaf with two Spam rows and one Legitimate row contributes a Spam probability of 2/3. For example, leaf probabilities of 0.49, 0.49 and 0.99 give two Legitimate hard votes, while the mean Spam probability of about 0.657 predicts Spam. Scikit-learn’s Random Forest classifier picks the class with the largest mean probability.

      How would an ensemble predict a number?

      Suppose three regression trees estimate minutes until an email gets a reply. Train them on a different dataset containing actual reply times. For one email they might predict 9, 11 and 13 minutes. Their mean is (9 + 11 + 13) ÷ 3 = 11 minutes. These times illustrate regression. The Spambase rows supply class labels.

      How do we get different trees?

      Draw rows for trees and features for splits

      If every tree can consider dollar signs at every split, several trees might lean on the same clue. A Random Forest draws a candidate set of features at each node. This gives other clues a chance to shape the tree.

      1. Which emails does this tree learn from? The bootstrap draw picks rows for the whole tree. Each copy of a row adds one count to its class.
      2. Which features can this node use? A feature draw chooses candidate columns. The draw at the next node is fresh.
      3. What is the best available split? Among its candidates, the tree picks the question that most reduces weighted Gini impurity for the rows at that node.

      Change the candidate features at each node

      Keep Tree 2’s 12 training draws fixed and replay different candidate draws. The root sends its rows to the Yes or No child. A mixed child tries cutoffs on its own list of candidates.

      Properties of base learners

      Give each tree enough room to learn

      A useful base learner should find some signal in the emails. We also want the trees to make different mistakes, so their average can be more stable.

      When a tree is too simple

      A single split can miss a pattern that depends on two features. If the model repeatedly misses such a pattern, it is underfitting and can have high bias.

      When a tree learns its tray too well

      A deep tree can learn useful combinations, but it can also fit patterns peculiar to a few training rows. If those patterns hurt performance on new emails, we call it overfitting.

      Change the maximum depth

      Maximum depth limits how many questions an email can answer. All three trees refit on their original bootstrap samples.

      The diagram shows Tree 3. Each card counts correct predictions on its own training tray. A row drawn twice counts twice.

      What can a second question learn?

      Depth 0 makes one prediction for all emails. At depth 2 the second question can differ depending on the first answer. A tree might examine exclamation marks only in emails with almost no dollar signs. This is an interaction. Extra questions can also learn quirks specific to the training draw.

      What if every tree makes the same mistake?

      The ensemble repeats that mistake. Varying trees is helpful when they still learn useful patterns and their errors differ across emails.

      Change one forest setting at a time

      Start with tree depth. Watch what happens to the score on training folds and the score on validation folds as the trees can ask more questions. Then try changing the number of trees, the feature budget, and the two limits on node size.

      Is the parent big enough to try?

      min_samples_split checks the parent before a split. A node with 10 rows qualifies at a minimum of 8. At a minimum of 11, it stays a leaf.

      Would both children be big enough?

      min_samples_leaf checks each proposed child. With a minimum of 3, a 9 | 1 split is ruled out while a 6 | 4 split clears that requirement.

      Which other settings can I change?

      criterion changes how a split is scored. max_leaf_nodes caps leaves, min_weight_fraction_leaf sets a minimum share of sample weight per leaf, and min_impurity_decrease requires a minimum weighted impurity drop. The search ranges should reflect the data size and the job the model has to do.

      Why balanced accuracy?

      On a hypothetical set of 90 legitimate emails and 10 spam emails, a model that always says Legitimate gets 90 out of 100 right. Its Spam recall is zero. Balanced accuracy gives the two classes equal weight by averaging their recall scores. In this example, (100% + 0%) ÷ 2 = 50%.

      Interview questions

      Explain importance and tune the trade-offs

      A colleague asks which clues the spam classifier relied on and how to make its trees simpler. Go back to the three trees you traced. Credit their dollar-sign and exclamation-mark splits before comparing settings.

      How does a forest compute feature importance?

      Every draw reaches the first split. A follow-up question only affects the emails on its branch. Impurity-based feature importance gives a question more credit when it separates the labels well and reaches more rows.

      Multiply each split’s impurity decrease by the fraction of training draws that reached it. Credit the feature used at that split. Add the credits for each feature, express them as shares of that tree’s total, then average those shares across the trees.

      A splitting tree contributes zero for each feature it never uses. The ensemble average includes those zeros. Scikit-learn omits root-only trees when averaging these importances.

      Work through the numbers for these trees

      A feature with many possible cutoffs gets more chances to earn split credit. For a check on fresh data, shuffle the dollar-sign frequencies among the held-out emails, keep each email’s other information in place, and score the same forest again. The score drop measures how much the forest relied on that feature in this test. This is permutation importance.

      Five settings, five different changes

      Pick one setting. Imagine keeping the other four fixed, then say which part changes. Does it affect the training tray, the questions a tree can ask, or the number of predictions we combine?

      Why can more trees give diminishing returns?

      If several trees already tend to give the same email the same answer, another similar tree adds little new information. More trees can steady the average and also take longer to train and use. Compare how much each increase improves the validation score.

      How do depth and pruning differ?

      Maximum depth caps how many questions an email can answer while the tree grows. Pruning checks whether a branch earns its extra size by improving the separation of the labels. A larger ccp_alpha makes that size more costly, so simpler trees are favored. A simpler tree may vary less with the training sample and also miss a useful pattern.

      When does a branch earn its place?

      Compare two possible subtrees in an illustrative spam-filter example. The four-leaf subtree separates the training labels better, so it has lower weighted leaf impurity. Each extra leaf comes with a cost. Move the penalty slider and watch which subtree becomes cheaper.

      Cost = weighted leaf impurity + α × number of leaves. Weighted leaf impurity adds each leaf’s impurity multiplied by its share of training weight.

      These are two illustrative pruning candidates. Starting with a fitted tree, cost-complexity pruning considers simpler subtrees. max_depth constrains the questions while the tree grows.
