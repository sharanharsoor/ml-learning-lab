Run your first notebook cells

A notebook alternates between text cells and code cells. A running Python session remembers names and their values. Run the setup cells first so the later cells have the values they need.

  1. Connect. Open the notebook in Colab and click Connect to start the Python session.
  2. Run. Click a cell’s play button or press Shift + Enter. Read its output underneath.
  3. Restart. If you want a fresh session, use the restart option under Runtime, then run the cells from the top. Restarting clears the variables in memory. The cell text stays in the notebook.

What does the Python syntax mean?
  • name = value saves a value under a name. Here hours_seen = 456 saves the number of historical observations used in this forecast.
  • [421, 734, 403] is an ordered list of three measured counts. Python starts counting list positions at zero, so [421, 734, 403][0] is 421.
  • def defines a reusable calculation. In Cell 2, forecast(rentals_total, hours_seen) calls that function with real values. return sends its result back to the line that called it.
  • import pandas as pd loads a library of table tools and gives it the short name pd. pd.read_csv(...) calls a tool from that library.

Here are the October 26 counts at 07:00, 08:00, and 09:00. len counts the entries. A for loop runs the indented line once for each entry.

october_26_counts = [421, 734, 403]
print("First value:", october_26_counts[0])

Why might a cell raise NameError?

If you call forecast before running the cell that defines it, Python has no value under that name. Run the definition first. Restart and rerun the notebook from the top when you want to check that the cells work in order.

See the same filter and group calculation in pandas 
cutoff = "2012-11-01"
history = rows.loc[rows["date"] < cutoff]
workday_eight = history.loc[(history["hour"] == 8) & (history["workingday"] == 1)]
display(workday_eight)

group_totals = history.groupby(["hour", "workingday"])["rentals"]
preview_summary = group_totals.agg(["count", "sum"])
display(preview_summary.loc[(8, 1)])

= assigns a value to a name. == tests equality for each row. & requires both tests to pass. .loc keeps the rows that pass the condition.

groupby puts each combination of hour and day type in its own group. agg counts the recorded rows and adds their rentals. The last .loc looks up the group labeled (8, 1). On the excerpt it returns count = 2 and sum = 1355. The notebook’s next section uses the saved full-history aggregates for the forecast.

Use a list of column names inside brackets to get a table, and a single column name to get a one-dimensional series. .to_numpy() changes each into an array with the same values and dimensions.

Check your calculation

The training group has 108,510 rentals over 456 hours. 108,510 ÷ 456 ≈ 237.96, so the forecast is 238. The recorded count is 331. 331 − 238 = +93 rentals. A positive residual means the observed count was higher than the prediction.
