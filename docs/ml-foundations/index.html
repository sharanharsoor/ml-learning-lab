Fit, predict, evaluate

  1. Fit

    Learn a value or rule from past examples. Here we calculate a typical 08:00 count from past workdays.

  2. Predict

    Use what the model learned to estimate an outcome for a new hour. This use of a fitted model is also called inference.

  3. Evaluate

    Compare the prediction with the recorded count. Repeat on many unseen hours to judge how well the model works.

What makes this a learned model?

We chose the rule “average past hours with matching calendar features.” The number it returns comes from data. A different training period could give a different average. A rule like “display Closed when the station status is Closed” can simply use a known status. Forecasting requires estimating an outcome that has yet to happen.

What is a baseline?

A baseline is a reference method for a comparison. The historical average is a simple baseline for a later, more complex forecast. In Unit 4 we’ll also compare this calendar forecast with an even simpler method that uses one historical average for every hour.

What answer do we need?

Regression and classification learn from examples with known targets. That’s supervised learning. Clustering is one kind of unsupervised learning.

What does the Python syntax mean?
  • name = value saves a value under a name. Here hours_seen = 456 saves the number of historical observations used in this forecast.
  • [421, 734, 403] is an ordered list of three measured counts. Python starts counting list positions at zero, so [421, 734, 403][0] is 421.
  • def gives a calculation a name. The function takes inputs inside parentheses and return sends its result back to the caller. The indented lines belong inside that function.
  • import pandas as pd loads a library of table tools and gives it the short name pd. pd.read_csv(...) calls a tool from that library.
Why might a cell raise NameError?

If you call forecast before running the cell that defines it, Python has no value under that name. Run the definition first. Restart and rerun the notebook from the top when you want to check that the cells work in order.

Understand the data before fitting a model

The workday forecast came from averaging older 08:00 counts. Look at those rows first. How much do the counts vary, and is it useful to group workdays and non-workdays separately?

Read a real row

The dataset records rental counts in one-hour intervals. This training example describes 08:00 to 08:59 on Thursday, October 25, 2012. It comes one week before the forecast case.

What does the temperature number mean?

UCI stores temperature divided by 41. A stored value of 0.52 corresponds to 0.52 × 41 = 21.32 °C. The source figure was already normalized, so this conversion gives the approximate temperature represented by the stored value.

What should you do with the weather code?

The archive stores clear conditions as 1 and mist or clouds as 2. What does the difference of 1 measure?

Why divide the variance by five here?

We describe the spread of these exact five hours, so we average their five squared distances. In a statistics lesson that estimates a wider population’s variance from a random sample, the usual sample variance uses n − 1. These five consecutive hours are a descriptive slice of one morning.

When would I use the median?

Toggle the what-if and watch the mean move while the middle place in the sorted list stays the same. A median can describe a typical observation or serve as a baseline when large counts pull the mean upward. The forecasting example in this course uses the mean of historical records for the same hour and day type.

Look for patterns across many days

Keep the hour at 08:00 and switch the day type. The histogram groups rental counts into ranges. The scatterplot pairs each hour’s recorded temperature with its rental count. Both use earlier records from January 2011 through October 2012.

Why inspect workdays and non-workdays separately?

At 08:00, the two groups in these training records have different distributions. A single shared average would mix them. The day-type comparison motivates a forecasting feature we can know in advance. It also helps us spot which subgroups have fewer examples.

Does the scatterplot prove that temperature changes demand?

It shows recorded pairs for this date range. Temperature moves with season and weather, and the number of riders can also change over time. To estimate the effect of temperature itself, we would need a study that accounts for these other differences.

What changes when the target is a category?

Count how many examples carry each target label. This is the class balance. In the full Spambase file, 1,813 of 4,601 emails are Spam (about 39.4%) and 2,788 are Legitimate (about 60.6%). A group count such as the number of bike workdays describes an input feature. A class count describes the outcome the classifier is trained to predict. UCI Spambase dataset

Check what the dataset recorded

An unusually high or low count is a clue to investigate. Compare it with similar hours, check the source, and record your decision before modeling. Rush hour can make a high count entirely plausible.

What do I do if I find a data problem?

Confirm what the field or row represents. If a measured target is missing, look for a source that can supply it before using that observation as a labeled training example. For missing inputs, a simple starting point is to fill numerical values with the training median and record which values were missing. For repeats, confirm the real unit of observation before deduplicating. Document the reason for any correction.

Test whether a model generalizes

We forecast 470 rentals for 8 a.m. on November 1, 2012. Capital Bikeshare recorded 680. Our forecast missed by 210 rentals. Would the same method work across many future hours?

Learn from the past, then test on later hours

Generalization means making useful predictions on new rows outside the training set. We keep the order of the calendar because the job is to predict future rentals.

  1. 1. Train Jan 2011 to Sep 2012
  2. 2. Validate Oct 2012
  3. 3. Test Nov to Dec 2012

Fit two candidate rules

  • Overall mean baseline gives every hour the same forecast. It rounds the average of all training counts.
  • Calendar model groups training rows by hour and workday status. It rounds the average within the matching group.

A baseline sets a reference point. We can ask how much prediction error the calendar model saves over a rule that ignores the hour.

Choose using validation error

Forecast October using the rules fitted through September. For each hour, take the absolute difference between prediction and actual. Divide the total miss by the number of hours to get mean absolute error, or MAE. Lower is better.

October validation results · Bars use a 0 to 200 rental scale
RuleTotal absolute error ÷ hoursMAE

October favors the calendar model. Lock the rule and then recalculate its means using all rows through October 31. Refit the baseline on the same past rows so both methods use the same information.

The rule is locked

The calendar model was selected using October. Its group averages now use January 2011 through October 31, 2012. The baseline uses the same rows and forecasts 189 rentals for every test hour.

At 08:00 on November 1 we know it is a workday. The calendar forecast is round(214,195 ÷ 456) = 470 rentals. Every count in that average comes from before November 1.

Measure performance on the final test period

The test contains 1,460 recorded hours. Score the chosen calendar model once and compare it with the baseline we set up at the start.

The calendar model misses by about 63.52 rentals per hour on average over this test period. Compare that with the 210-rental miss we saw at 8 a.m. A single miss and an average miss answer different questions.

Why can we train again on October after choosing?

October had two jobs in sequence. First its labels checked the candidates fitted through September. Once the calendar rule won, October became extra historical training data for estimating the group averages. November and December still stayed outside both steps.

Why can October have a higher error than the test months?

They cover different dates. November and December have a different mix of rental counts and the final rules are refitted on more history. The difference in errors alone cannot tell us how much each factor contributed.

Choose a split that matches how predictions will be used

Decide what must be new at test time. Select a scenario to see what should be kept apart.

    Can two split requirements apply together?

    Yes. Repeated emails from the same campaign might need to stay together while each split still contains enough spam to measure recall. Group integrity comes first. With a forecasting task, the final test must remain later in time even if class proportions change.

    Would this information be available at 7:59 a.m.?

    Data leakage happens when unavailable information slips into training, prediction, or model selection. Use the same recorded hour to test a shortcut.

    Recorded total
    Absolute error

    The source file records totals for casual and registered riders. Their sum gives the target by definition. It is a valid accounting identity after the hour and a leaky input before the hour. UCI Bike Sharing dataset and data dictionary

    How do duplicates and preprocessing leak information?
    • Duplicate rows. A copied test email in training lets a model see the same example and its label early. Drop verified duplicates or keep related copies in one split before evaluating.
    • Preprocessing. If you fill missing training values with a mean computed over all rows, that mean already depends on future rows. Fit the mean, category encoding, or scaling rule on training rows and apply the fitted rule to validation and test rows.
    • Repeated testing. Trying many models and selecting the one with the best test result uses that test for model selection. Make those choices on validation and reserve an independent final check.

    Reproduce the decision in Python

    The notebook reads all 17,379 records, fits both rules, and runs this sequence. Each mean uses the rows passed to fit_rules.

    candidates = fit_rules(train)
validation_errors = evaluate(candidates, validation)
chosen = min(validation_errors, key=validation_errors.get)

final = fit_rules(train + validation)
test_errors = evaluate(
    {chosen: final[chosen], "Overall mean": final["Overall mean"]},
    test,
)

    evaluate returns one MAE per rule. The selected name is Calendar model. The final call also reports the overall mean reference.
