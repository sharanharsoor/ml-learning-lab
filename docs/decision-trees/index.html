Some cuts leave the labels more mixed than others. Entropy gives us a way to score how mixed they are.

Start with surprise

Score one node

From surprise to entropy

Picture drawing one random parcel from a node. How surprising would its label be?

Start with inverse probability

Rarer labels give a larger 1/p. For a certain label, p = 1 gives 1/p = 1. We want certainty to contribute zero information.

Take the logarithm

I(p) = log₂(1/p) = −log₂(p). It maps certainty to zero and makes the surprises of independent outcomes add, because their probabilities multiply. For two independent outcomes with probability ½ each, the joint probability is ¼ and the surprise is 2 bits. Base 2 gives the unit.

Check the weighting at a 25% Review share

Set the slider to 25%. Auto has probability ¾, so its surprise is about 0.415 bits. Review has probability ¼, so its surprise is 2 bits. Multiply by the two shares and add. ¾ × 0.415 + ¼ × 2 ≈ 0.811 bits.

The base of the logarithm sets the unit. Base 2 gives bits. The natural logarithm gives nats and rescales every entropy gain by the same positive constant.

Entropy is the average surprise. If you averaged one surprise per row, a label that appears in four out of eight rows would show up four times. Grouping those rows gives H = −Σ p(label) log₂ p(label). Sum over distinct labels. A label with probability zero contributes zero by the limit of −p log₂ p.

A good question lowers the uncertainty that remains. There’s another way to measure the same label mix, using the chance of a mismatch.

Choose a measure of impurity

Gini vs entropy

Entropy averages surprise. Gini impurity measures the chance that two draws from a node have different labels. In a decision tree, Gini index is another name for this node score.

Draw two labels, with replacement

Draw one parcel, return it to the node, then draw again. Each draw uses the same label probabilities.

Why the square?

For label k, the first draw has probability pₖ and a different second label has probability 1 − pₖ. Multiply and sum over the first label to get G = Σ pₖ(1 − pₖ) = 1 − Σ pₖ². The square is the probability of drawing the same label twice.

What changes with more labels?

A pure node gives 0 by both scores. Both scores peak when the K labels are equally common. With a uniform mix, the second draw matches whichever label came first with probability 1/K, so G = 1 − 1/K. Each label is equally surprising, so entropy is log₂(K) bits. For two labels the maxima are 0.5 and 1 bit.

Why start with Gini?

Gini uses squares and addition and avoids logarithms, so it can be cheaper to compute per candidate. It is the default in scikit-learn’s DecisionTreeClassifier. Actual training time depends on the data and implementation. If the choice matters, compare both criteria with the same validation setup and select the one that serves your metric. scikit-learn criterion reference

How thresholds become candidates

Exact search tries a midpoint per gap between distinct weights. Coarse search tries only 2.5, 4.5, and 6.5 here. It sums the label counts on both sides of each edge. Packaging A versus B adds its own candidate in either mode. Try both search modes while the criterion is Entropy. Exact search finds weight 3.5 at about 0.549 bits of gain. With the coarse edges, weight 2.5 and packaging A tie at about 0.311 bits.

What about categorical features and scaling?

The feature Y has values A and B, so one yes-or-no question separates them. With more categories, a binary tree can test membership in a group of categories, or test one category at a time after one-hot encoding. Multiway trees can use more than two branches. Each branch still earns its weight from the same immediate parent.

For an exact numerical search, a strictly increasing rescaling preserves the ordering of the training values and therefore the candidate partitions. The cutoff itself changes units. A tree can also reuse a feature deeper down when a different cutoff still divides the rows.

Control model complexity

Where should the tree stop?

Add questions when they help on unseen data. A tree underfits when it misses useful patterns. It can overfit when extra questions capture details specific to the training rows.

When growth stops at a node

A pure node can stop. A mixed node can also stop if it reaches the depth limit, can’t give both children the required number of rows, or has no eligible split with enough gain. These rules limit growth during fitting.

How to choose the limit

Compare depth and leaf-size settings using validation data or cross-validation. Keep an independent test set for the final estimate. When you use the six held-out parcels here to choose depth, they serve as validation data.

Compare the same tree before and after pruning

Cost-complexity pruning compares weighted leaf impurity + α × leaf count. The parcel tree has three pure leaves and 0 remaining entropy. Removing the packaging question leaves two leaves and 0.4512 bits. Keeping just the root leaves one leaf and 1 bit.

Now look back at the fitted tree and ask how much each feature contributed to the reduction in training impurity.

Attribute the reduction

Give each feature credit

A feature earns credit every time the fitted tree uses it. Multiply the local gain by the share of all training rows that reached the node, then add the credits by feature.

Why multiply by the root share?

Pick one training row at random. It reaches a node of size n with probability n/N, where N is the root size. The split improves the label mix by its local gain for the rows that reach it. Averaged over all rows, its contribution is (n/N) × local gain.

What do all those credits add up to?

Each split replaces the parent’s impurity contribution with its children’s contributions. When you add the reductions, internal nodes cancel. What remains is the root impurity minus the weighted impurity of the final leaves.

Each chosen split’s contribution to feature importance
Chosen splitRoot shareLocal gainCredit

Divide each feature’s credit by the total credit to report its share. One strong split near the root can earn more than several small splits. This score describes how this fitted tree reduced impurity on its training data.

What if two features measure nearly the same thing?

A split credits the feature the tree actually chose. If weight and another measurement are interchangeable, either one can get most of the credit while the other earns little. Importance describes the fitted model, so it can move when the data, features, or depth change.

Permutation importance asks a different question. After fitting, shuffle one feature across validation rows and check how much the score drops. A feature with a close substitute can have a small drop. Neither calculation establishes that changing a feature would cause the real-world outcome to change.

    See this cutoff as a regression tree

    The cutoff search compares weighted child scores using the rows in the immediate parent. Each child gets its own mean and MSE. A fitted regression tree predicts one constant per leaf.

    Use MSE to compare candidate cuts. Its units are minutes squared. After the tree predicts new timed parcels, take the square root of their average squared error to report RMSE in minutes.

    Why does the mean minimize squared error?

    For any constant prediction c, the average squared error equals MSE at the mean + (c − mean)². That extra square is smallest at zero, which is exactly when c equals the mean. The tree uses that best constant separately in each child while choosing a split.

    Read the runnable Python
    
      from collections import Counter
from math import log2
from statistics import mean

# X, Y, class (0 = Auto, 1 = Review), processing time in minutes
train = [
    (1, "A", 0, 2), (2, "B", 0, 2), (3, "B", 0, 2), (4, "B", 1, 6),
    (5, "B", 1, 8), (6, "B", 1, 8), (7, "A", 0, 4), (8, "B", 1, 8),
]
held_out = [
    (2, "A", 0), (3, "B", 0), (5, "B", 1),
    (8, "B", 1), (6, "A", 1), (7, "B", 0),
]


def entropy(rows):
    counts = Counter(row[2] for row in rows)
    probabilities = [count / len(rows) for count in counts.values()]
    return -sum(p * log2(p) for p in probabilities)

def split(rows, goes_left):
    left, right = [], []
    for row in rows:
        (left if goes_left(row) else right).append(row)
    return left, right

def weighted_score(children, score):
    total = sum(map(len, children))
    return sum(len(child) * score(child) for child in children) / total

weight_cut = split(train, lambda row: row[0] <= 3.5)
package_cut = split(train, lambda row: row[1] == "A")
print(f"Root entropy: {entropy(train):.6f} bits")
for name, children in [("X <= 3.5", weight_cut), ("Y == A", package_cut)]:
    after = weighted_score(children, entropy)
    gain = entropy(train) - after
    print(f"{name}: weighted entropy = {after:.6f}, gain = {gain:.6f}")

def predict_class(x, y):
    if x <= 3.5:
        return 0
    return 0 if y == "A" else 1

predictions = [predict_class(x, y) for x, y, actual in held_out]
matrix = [[0, 0], [0, 0]]
for (_, _, actual), prediction in zip(held_out, predictions):
    matrix[actual][prediction] += 1
print(f"Held-out predictions: {predictions}")
print(f"Confusion matrix (actual rows, predicted columns): {matrix}")

def leaf_mean(rows):
    return mean(row[3] for row in rows)

def mse(rows):
    center = leaf_mean(rows)
    return mean((row[3] - center) ** 2 for row in rows)

left_mean, right_mean = map(leaf_mean, weight_cut)
print(f"Leaf means at X <= 3.5: {left_mean:.1f} and {right_mean:.1f} minutes")
after = weighted_score(weight_cut, mse)
print(f"Weighted child MSE: {after:.6f} minutes squared")
print(f"MSE reduction: {mse(train) - after:.6f} minutes squared")

      from sklearn.metrics import confusion_matrix
from sklearn.tree import DecisionTreeClassifier, DecisionTreeRegressor

def features(rows):
    return [[row[0], int(row[1] == "B")] for row in rows]

inputs = features(train)
classifier = DecisionTreeClassifier(
    criterion="entropy", max_depth=2, random_state=0
).fit(inputs, [row[2] for row in train])
labels = [row[2] for row in held_out]
predicted = classifier.predict(features(held_out))
matrix = confusion_matrix(labels, predicted, labels=[0, 1])
print(f"Confusion matrix (actual rows, predicted columns): {matrix.tolist()}")

regressor = DecisionTreeRegressor(
    criterion="squared_error", max_depth=1, random_state=0
).fit(inputs, [row[3] for row in train])
low, high = regressor.predict(features([(1, "A"), (5, "B")]))
print(f"Regression leaf means: {low:.1f} and {high:.1f} minutes")
